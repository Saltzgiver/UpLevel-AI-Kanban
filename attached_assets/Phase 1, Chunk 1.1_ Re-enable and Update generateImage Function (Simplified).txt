Phase 1, Chunk 1.1: Re-enable and Update generateImage Function (Simplified)
This document outlines the first step in integrating OpenAI's gpt-image-1 model, removing the DALL-E 3 fallback for a simpler implementation.
Goal: Modify the generateImage function in server/openai.ts to only use the gpt-image-1 model for image generation.
Context:
* The file to modify is server/openai.ts.
* The generateImage function currently exists but is temporarily disabled.
* The function needs to be updated to use the openai.images.generate method.
* We will not implement fallback logic to DALL-E 3 in this simplified version.
* gpt-image-1 primarily returns base64-encoded image data (b64_json).
* Detailed logging is required to track the process.
Implementation Plan:
1. Locate generateImage: Open the server/openai.ts file and find the generateImage asynchronous function.
2. Remove Disabling Code: Remove the line that throws the "Image generation functionality has been temporarily removed..." error.
3. Implement API Call: Inside the generateImage function, add the core logic to call the OpenAI API.
   * Use openai.images.generate({...}).
   * The prompt parameter should be the prompt argument passed to the generateImage function.
   * Crucially, set the model parameter explicitly to "gpt-image-1".
   * Set the response format to response_format: "b64_json". This is the expected format from gpt-image-1.
   * Set n: 1 for a single image generation.
   * Consider adding size and quality parameters if needed (e.g., "1024x1024", "standard" or "auto").
4. Simplify Error Handling:
   * Wrap the openai.images.generate call in a try...catch block.
   * In the catch block, log the error and re-throw it. Do not implement any fallback logic to DALL-E 3. The system will rely solely on the gpt-image-1 API call succeeding.
5. Handle Response Format:
   * After a successful API call, expect result.data[0].b64_json to exist.
   * Return an object like { base64: result.data[0].b64_json, fileType: 'image/png' } (defaulting to png for now, more robust type detection will be in Chunk 1.3). Do not handle the url response format here.
6. Add Detailed Logging: Add console.log statements at key points within the function:
   * At the start, logging the prompt and API key source.
   * Before making the API call, logging that gpt-image-1 is being used and the parameters.
   * After a successful call, logging success and the base64 length received.
   * In the catch block, logging the error.
   * Before returning the final result, logging that base64 data is being returned.
   * Refer to the specific logging instructions in the provided attached_assets/for each recommendation i wanted the prd and impl....txt for guidance on log content, adjusting to remove DALL-E specific messages.
Testing Plan:
1. Create Test Script: Create a new Node.js script file (e.g., server/tests/test-generate-image-backend.js).
2. Import: Import the generateImage function from server/openai.ts.
3. Direct Call: Write an asynchronous function that calls generateImage with a simple text prompt (e.g., "A futuristic cityscape").
4. Log Output: Log the result returned by generateImage.
5. Run Test: Run the script.
   * Expected Outcome: The server logs should explicitly show gpt-image-1 being used. The script output should contain an object with a base64 string and a fileType. No logs related to DALL-E or fallback attempts should appear.
6. Verify Logging: Review the server console output to ensure the detailed logging messages are present and accurately reflect the execution flow and the use of gpt-image-1.
