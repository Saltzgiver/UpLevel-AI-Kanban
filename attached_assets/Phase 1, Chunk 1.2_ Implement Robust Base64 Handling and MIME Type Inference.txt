Phase 1, Chunk 1.2: Implement Robust Base64 Handling and MIME Type Inference
This document outlines the next step in integrating OpenAI's gpt-image-1 model: implementing robust handling for base64-encoded image data and reliable MIME type detection. This is particularly important as gpt-image-1 primarily returns images in base64 format.
Goal: Create helper functions in server/openai.ts to clean and validate base64 strings and to infer image MIME types from binary data.
Context:
* The file to modify is server/openai.ts.
* gpt-image-1 responses often contain base64-encoded image data (b64_json).
* Base64 strings can sometimes contain invalid characters or incorrect padding, which can cause issues when decoding or storing.
* Accurate MIME type detection is necessary to store the correct fileType in the database and serve the image correctly in the frontend.
* MIME types can often be inferred by examining the initial bytes (file signature) of the image data.
* Detailed logging is required to track the process.
Implementation Plan:
1. Open server/openai.ts: Access and open the server/openai.ts file for editing.
2. Create cleanBase64 Helper: Add a new helper function cleanBase64(base64String: string): string within this file.
   * This function should take a base64 string as input.
   * Inside the function, implement the following cleanup steps as described in the implementation notes [cite: attached_assets/for each recommendation i wanted the prd and impl....txt]:
      * Trim leading/trailing whitespace.
      * Remove any characters that are not valid base64 characters (A-Z, a-z, 0-9, +, /, =).
      * Ensure the string length is a multiple of 4 by adding padding (=) if necessary.
   * Add logging within this function to show the original length, cleaned length, and potentially a snippet of the cleaned string for debugging [cite: attached_assets/for each recommendation i wanted the prd and impl....txt].
   * Include a check for a minimum length after cleaning (e.g., if the cleaned string is very short, it's likely invalid) and log a warning or throw an error.
3. Create inferMimeTypeFromBuffer Helper: Add another new helper function inferMimeTypeFromBuffer(buffer: Buffer): string | null within server/openai.ts.
   * This function should take a Node.js Buffer containing image data.
   * Inside the function, check the initial bytes of the buffer for common image file signatures:
      * PNG: [0x89, 0x50, 0x4E, 0x47]
      * JPEG: [0xFF, 0xD8, 0xFF] (check the first 3 bytes)
      * GIF: [0x47, 0x49, 0x46, 0x38, 0x37, 0x61] or [0x47, 0x49, 0x46, 0x38, 0x39, 0x61] (check the first 6 bytes)
      * WebP: Check bytes at offset 8 for [0x57, 0x45, 0x42, 0x50] within the "RIFF" header (requires checking bytes 0-3 for "RIFF" and bytes 8-11 for "WEBP").
      * Add checks for other common image formats if desired.
   * Return the corresponding MIME type string (e.g., 'image/png', 'image/jpeg') if a signature is matched.
   * Return null if no known signature is found or if the buffer is too small to contain a signature.
   * Add logging within this function to indicate which signature was detected or if detection failed [cite: attached_assets/for each recommendation i wanted the prd and impl....txt].
