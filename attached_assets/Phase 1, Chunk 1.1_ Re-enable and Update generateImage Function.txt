Phase 1, Chunk 1.1: Re-enable and Update generateImage Function
This document outlines the first step in integrating OpenAI's gpt-image-1 model into the AI Kanban application: re-enabling and updating the core image generation function in the backend.
Goal: Modify the generateImage function in server/openai.ts to use the gpt-image-1 model for image generation, implementing fallback logic to DALL-E 3 based on configuration or API errors.
Context:
* The file to modify is server/openai.ts.
* The generateImage function currently exists but is temporarily disabled and throws an error.
* The function needs to be updated to use the openai.images.generate method from the OpenAI Node.js client.
* The application uses environment variables, including PREFER_DALLE_FALLBACK, and potentially column-specific API keys, which should influence model selection.
* gpt-image-1 primarily returns base64-encoded images (b64_json), while DALL-E 3 returns a url. The function needs to handle both.
* Detailed logging is required to track the process.
Implementation Plan:
1. Locate generateImage: Open the server/openai.ts file and find the generateImage asynchronous function.
2. Remove Disabling Code: Remove the line that throws the "Image generation functionality has been temporarily removed..." error.
3. Implement API Call: Inside the generateImage function, add the core logic to call the OpenAI API.
   * Use openai.images.generate({...}).
   * The prompt parameter should be the prompt argument passed to the generateImage function.
   * Set the default model parameter to "gpt-image-1".
   * Request the response format as response_format: "b64_json" for the gpt-image-1 call.
   * Request n: 1 for a single image generation.
   * Consider adding size and quality parameters if needed, referencing available options for gpt-image-1 (e.g., "1024x1024", "standard" or "high"). The search results indicate gpt-image-1 supports "1024x1024", "1024x1536", "1536x1024", and "auto" sizes and "low", "medium", "high", "auto" quality [cite: search results]. Start with "1024x1024" and "standard" or "auto" for simplicity.
4. Implement Model Selection and Fallback:
   * Before making the API call, check the PREFER_DALLE_FALLBACK environment variable. If it's set to "true", set the model parameter for the API call to "dall-e-3" and request response_format: "url".
   * Wrap the openai.images.generate call in a try...catch block.
   * In the catch block, check if the error indicates a problem specific to gpt-image-1 (e.g., related to organization verification, which might appear in the error message). If such an error occurs and PREFER_DALLE_FALLBACK is not set to "true", attempt the call again with the dall-e-3 model and response_format: "url". Add logging to indicate that a fallback is being attempted and the reason.
   * If the fallback call also fails, re-throw the error.
5. Handle Response Formats:
   * After a successful API call, inspect the response structure (result.data[0]).
   * If result.data[0].url exists, the response is a URL (likely from DALL-E 3). Return an object like { url: result.data[0].url, fileType: 'image/png' } (defaulting to png, or try to infer from URL if possible, but this is less reliable).
   * If result.data[0].b64_json exists, the response is base64 (likely from gpt-image-1). Return an object like { base64: result.data[0].b64_json, fileType: 'image/png' } (defaulting to png for now, more robust type detection will be in Chunk 1.3).
6. Add Detailed Logging: Add console.log statements at key points within the function:
   * At the start, logging the prompt and API key source.
   * Before making the API call, logging the model and parameters being used.
   * After a successful call, logging the model used and the response format received (URL or base64 length).
   * In the catch block, logging the error and whether a fallback is attempted.
   * Before returning the final result, logging the type of data being returned (URL or base64).
   * Refer to the specific logging instructions in the provided attached_assets/for each recommendation i wanted the prd and impl....txt for exact log messages.
Testing Plan:
1. Create Test Script: Create a new Node.js script file (e.g., server/tests/test-generate-image-backend.js).
2. Import: Import the generateImage function from server/openai.ts.
3. Direct Call: Write an asynchronous function that calls generateImage with a simple text prompt (e.g., "A colorful abstract painting").
4. Log Output: Log the result returned by generateImage.
5. Run Test (Default): Run the script with your default Replit environment variables.
   * Expected Outcome: The server logs should show gpt-image-1 being used. The script output should contain an object with a base64 string and a fileType.
6. Run Test (Fallback Enabled): Set the PREFER_DALLE_FALLBACK environment variable in Replit to "true". Run the script again.
   * Expected Outcome: The server logs should show DALL-E 3 being used due to the fallback preference. The script output should contain an object with a url and a fileType.
7. Run Test (Fallback Triggered by Error): If possible (e.g., if your OpenAI account is not organization verified), remove the PREFER_DALLE_FALLBACK=true variable. Run the script.
   * Expected Outcome: The server logs should show an initial attempt with gpt-image-1, an error indicating the need for verification, and then a fallback attempt with DALL-E 3. The script output should contain an object with a url.
8. Verify Logging: Review the server console output for all test runs to ensure the detailed logging messages are present and accurately reflect the execution flow, model used, response format, and any errors.
