Phase 2, Chunk 2.1: Integrate Image Generation Trigger into Chat Endpoint
This document outlines the next step in integrating OpenAI image generation: modifying the backend API endpoint that handles new chat messages to detect image generation requests and trigger the AI processing workflow.
Goal: Update the relevant POST endpoint in server/routes.ts to identify user messages requesting image generation and initiate the backend process.
Context:
* The file to modify is server/routes.ts.
* The application has an existing API endpoint for creating new chat messages (likely a POST request to /api/chats or similar).
* This endpoint needs to check the content of incoming user messages.
* Image requests will be identified using specific keywords or patterns (likely defined in server/openai.ts).
* The image generation process should only be triggered if the associated Kanban column is configured for GPT interaction (column.gptAssigned).
* The actual AI processing (calling generateImage and handleFileGeneration) will happen asynchronously after the initial API response.
* Detailed logging is required to track the process.
Implementation Plan:
1. Open server/routes.ts: Access and open the server/routes.ts file.
2. Locate Chat Creation Endpoint: Find the POST route handler responsible for creating new chat messages. This likely involves receiving a cardId and content in the request body.
3. Identify Image Request Patterns: Import or define the array of image request patterns (e.g., imageRequestPatterns) that are used to detect image generation intent in a user's message. These patterns should match phrases like "generate an image," "create a picture," "draw," etc. (These patterns might already exist in server/openai.ts; if so, import them).
4. Implement Image Request Detection:
   * After receiving the cardId and user content, add logic to check if the content matches any of the imageRequestPatterns. A simple check using some() with a regular expression test or includes() might suffice.
   * Retrieve the column associated with the cardId from your database using storage.
5. Conditional AI Triggering:
   * If an image request is detected and the retrieved column has gptAssigned set to true:
      * Call the triggerGPTProcessing function (or similar function that orchestrates the AI response generation in your application). This function will be updated in the next chunk (Chunk 2.2) to handle image generation specifically. Pass the cardId and the user's message content to this function.
      * Important: Ensure this call to triggerGPTProcessing is asynchronous (e.g., using await if it returns a Promise, or ensuring the function itself runs in the background). The API endpoint should respond quickly without waiting for the image generation to complete.
      * Set the card's processing flag to true in the database using storage.updateCard before returning the response. This indicates to the frontend that the card is being processed.
   * If an image request is detected but the column is not GPT-assigned, you might add a chat message response informing the user that image generation is not enabled for this column.
   * If no image request is detected, proceed with the standard chat message handling (saving the user message and potentially triggering a regular text-based AI response if applicable).
6. Return API Response: The API endpoint should return a success status (e.g., 201 Created or 200 OK) immediately after saving the user message and triggering the asynchronous AI process (or handling the non-image request).
7. Add Detailed Logging: Add console.log statements:
   * At the start of the route handler.
   * When an incoming message is identified as an image request.
   * When checking if the column is GPT-assigned.
   * When triggering the triggerGPTProcessing function for an image request.
   * When setting the card's processing flag.
   * If an image request is made for a non-GPT column.
   * In any catch blocks, logging errors.
Testing Plan:
1. Identify Endpoint: Determine the exact URL and HTTP method for the chat message creation endpoint (e.g., POST /api/chats).
2. Use API Client: Use a tool like curl, Postman, or write a simple Node.js script to send POST requests to this endpoint.
3. Test Image Request (GPT Column):
   * Create a card in a column that is configured for GPT interaction.
   * Send a POST request to the chat endpoint with the cardId and a message containing an image request pattern (e.g., {"cardId": "...", "content": "Generate an image of a cat."}).
   * Expected Outcome: The API should return a successful response quickly. The server logs should show the message being detected as an image request, the column being checked, and the AI processing being triggered. Check the database to confirm the user's message is saved and the card's processing flag is set to true.
4. Test Non-Image Request (GPT Column):
   * Use the same GPT-enabled card.
   * Send a POST request with a regular chat message (e.g., {"cardId": "...", "content": "What is the capital of France?"}).
   * Expected Outcome: The API should return a successful response. The server logs should show the message not being detected as an image request and the standard chat handling path being taken.
5. Test Image Request (Non-GPT Column):
   * Create a card in a column that is not configured for GPT interaction.
   * Send a POST request with an image request message (e.g., {"cardId": "...", "content": "Generate an image of a dog."}).
   * Expected Outcome: The API should return a successful response. The server logs should show the message being detected as an image request, the column not being GPT-assigned, and potentially a log indicating that image generation was skipped for this reason. Check the database to confirm the user's message is saved, but the card's processing flag should not be set to true.
6. Verify Logging: Review the server console output for all test runs to ensure the detailed logging messages are present and accurately reflect the logic flow for each scenario.
